# Write：论证、读者顺序和保真

本阶段采用用户维护的 Deli 本地 `academic-prose` / examples 与 PaperFlow 的证据绑定稿件方法，综合改写为当前阶段任务。它不包含 Deli 第三方原文，也不以 AI 检测器分数或强制句型判断论文质量。

## 输入与写作顺序

读取当前 Brief/逐项合同、venue 模板、文献核验、实验/图表记录、计划和已支持 claim。确认 venue 及图表计划校验通过后再进入正文。先确定每节替读者回答什么问题，再安排背景、方法选择、证据、解释和局限。

写研究对象、样本、条件与比较关系，不把编辑和运行顺序当论文主线；但预先设计、标签访问、数据复用及评价器修复等影响证据身份的时序必须保留。已暴露开发发现不能写成独立验证。摘要尽早交代具体问题、方法选择和发现，不能靠泛背景或功能列表制造动机。

方法先说明要估计什么、关键选择与假设，再给命名/公式。准确研究动作可以直接写 compare/test/design；术语可重复，不用生硬同义词换掉精确概念。段落已知对象和主判断保持清楚，修复名词堆、模糊 this/these、悬垂修饰和缺前提；长句或被动本身不构成错误。

## 逐 claim 保真

实质修订或搬移段落时保留基准版本，在修订记录写“位置、改法、理由、核对结果”。对照前后逐项核对：对象、指标、数据集、比较基线、分母、单位、区间、实验身份、引用归属、条件、否定/量词和结论强度。数字集合与 citation key 不变仍可能关系失真。

- 均值差异不是每个样本改善；有限搜索不是穷尽；相关不是因果。候选解释不能升为机制证明。
- 清楚的观测/证明不因尚不能外推就无据弱化。只修饰受影响主张，不把整篇降成猜测。
- 引用紧邻支持的具体主张，分开背景相关、方法归属与本研究选择；移动引用后重新读支持范围。一篇文章不支持某模型不证明该模型为首次提出。
- 每个结果句给可核对对象、方向、数值/图表和适用条件，不让“Figure shows”替代发现。novel/robust/significant 等评价需对应实际证据；统计显著必须有适用检验，实际意义另说。

## 局限与案例操作

局限须指出影响哪项主张、改变何种可信度/解释/外推。动摇结论的缺陷必须修复或缩小结论，不能靠改名“研究范围”关闭；明确范围内成立的结果也不因未覆盖所有场景而失效。

必要边界就近说明，共同条件集中说明；合并重复保留时不丢分母、实验身份或反证。只有泛泛“仍需谨慎/进一步研究”且无新增信息时才删。结尾完整表达已经回答的问题，不机械采用先肯定再否定。

按问题执行对应本地案例操作：空泛动机改为真实缺口；读者顺序先选择后命名；图表导览改为发现；均值/区间/样本关系做双向核对；局限去重保留必需反例；已支持结论保持明确；引用移动后重查归属。案例只是操作示例，不能把其中数值或研究经历带入当前论文。

## 交接和失败

逐 requirement 将实际章节、图表引用、源 TeX、PDF、bib 和证据绑定；没有进入稿件的产物不算交付。输出源码与实际编译 PDF，保留编译日志、未定义引用/缺资产检查和保真记录。模板变更、错误绑定、数字关系漂移或未编译均退回对应阶段；不能用流畅度和总分弥补。

review 的新读者应先仅凭成稿复述问题、选择、主要发现与范围，再对照证据；修订说明不能替正文补逻辑。普通措辞修订不需要额外全套评审，但改变科学主张或证据必须重验相关项。
